# 収集と詳細調査の運用

通常の依頼・定期更新は **求人収集モード collect** を使います。「近い企業を詳しく」「応募条件を確定」などの依頼時だけ **詳細調査モード investigate** を使います。画面の確認済み・保留・未審査は求人の状態で、実行モードとは別です。画面の検索・ソート・フィルター・表示切り替えは変更していません。

|項目|求人収集 collect（既定）|詳細調査 investigate（明示）|
|---|---|---|
|目的|比較できる新規IT求人・企業の発掘|近い候補の応募条件の確認|
|探索先|求人媒体、公的情報、公式HP、採用管理ページ、構造化データ|選んだ求人の未確認項目の原典・同一求人別掲載|
|既存求人|重複照合に利用、判定・確認日を上書きしない|既定10件まで、対象IDも指定可能|
|未知の条件|未審査・保留へ保存、明確な不適合としない|不足理由を残して保留|
|公開|最低限の実在確認後、未審査で早期表示|厳密な応募資格・募集状況・通勤・待遇を満たせば確認済み|
|自動で行わないこと|プロフィール照合、既存全件の詳細審査、通勤時間の推測|研究・制作の企業実務への読み替え、未知の充足判定|

## 求人収集の手順

1. 宮口・浜北・都田・細江・三方原を先に、浜松・磐田のIT正社員募集を幅広く探す。求人検索だけでなく企業一覧・公式HPから採用ページへ進む。
2. 実在企業と**個別の募集**、IT職、勤務地の地域、出典URLを簡易確認する。給与等が欠けても詳細審査を待たない。
3. 既存キーまたは同一企業・職種の出典URLと重複する場合は統合候補として記録し、既存判定を変えない。同じ企業の別職種は残す。別媒体の同一求人・採用区分の差は人も照合する。
4. 明示的な非正社員・非IT・募集終了・期限切れは内部の除外記録へ。カテゴリ等が不明なら作業待ちへ。不明だけで除外しない。
5. 最低限の確認を終えた公開向け要約を登録し、未審査一覧で早期公開する。原典・確認日・未確認事項を必ず保持する。

```powershell
# ルート・venv有効状態。collectは--modeを省略しても既定。
python -m collector update --mode collect --import data/internal/import.csv --discoveries data/internal/new-summaries.json
# 明示的に許可を確認した取得先だけ
python -m collector update --mode collect --network --sources config/sources.yaml
```

CSVは company,title,address,url,description,kind。抽出だけでは応募可能にならず、内部の candidates.jsonl と collection-staging.jsonl に残ります。企業・採用ページのリンクは leads.jsonl に保存し、企業の存在だけを求人件数に数えません。アクセス不能・手動確認先も記録します。

new-summaries.json は既存の ReviewCandidate スキーマの配列です。id は取り込み対象の stable_id と一致させ、company/title/category/address/url/checked_at/summary/reasons を記入。status と stage は discovery、discovery_verified は true、regions に確認した地域を指定します。これは実在求人の最低限の確認を終えたことを人が明示する入力で、未確認の対象に付けてはいけません。facts は未確認なら空配列でよく、確認した項目だけ根拠URL・日付とともに登録します。

公開要約のURLは内部候補の出典に登録済みである必要があります。架空の求人を自動生成しません。求人資格を確認した場合も、このモードだけで確認済みへ昇格しません。既存求人の再発見で確認日を今日に更新しません。

## 詳細調査の手順

```powershell
# 対象候補のIDを表示するだけ。外部調査を実行したとは報告しない。
python -m collector queue --limit 10
# 選んだ求人の不足項目を調べ、根拠を修正したJSONを渡す
python -m collector update --mode investigate --ids 対象ID --import data/internal/reviewed.json
# 既存根拠の再判定だけなら--importなし
python -m collector update --mode investigate --limit 5
```

確認済み実経路が短い求人を先にし、時間不明の求人は近隣地域を優先します。地域帯から分数を作りません。対象ID以外の新規求人を詳細調査のインポートへ混ぜるとエラーになります。

必要な調査は人・利用可能な検索/閲覧手段で行い、コマンドは記録した証拠を照合します。外部調査や企業への問い合わせを自動で済ませる機能ではありません。応募資格、実務経験の定義、実配属、給与、休日、時間、募集状況、実経路を確認します。大学研究・個人制作を企業実務として数えません。公開情報で解決しない点は不足理由を残します。

## 定期実行と制約

GitHub Actions の Collect new job candidates は毎週月曜09:00 JSTと手動実行で収集だけを行います。プロフィールのSecretは不要です。MIYAJOB_SOURCES_YAML に許可済みソースがなければ「収集未実行・公開データ維持」と記録します。設定だけで検索・取得したことにはしません。

現時点の許可済み自動取得先は未設定です。今回、実際の新規外部収集や詳細審査は実行していません。件数は確認済み8・保留40・未審査67、閲覧115件のままです。

原典の利用条件・robots・頻度制限を守り、制限回避はしません。自動取得の結果は最低限の確認前には内部作業待ちです。公開向け提案ファイル2つだけを7日間artifactに保存し、私有プロフィールや内部履歴はアップロードしません。確認済み8件のファイルは収集で変更しません。公開データだけのCI checkoutでも既存の未審査・保留を消さないようにしています。取得失敗時は公開ファイルを保持し、提案の増加と実際の閲覧件数増加を分けて報告します。

手動調査で最低限を確認した候補は既存求人の詳細調査を待たず登録・デプロイできます。自動コミット・自動デプロイは行わず、公開前の品質チェックとPagesの手動実行を維持します。
